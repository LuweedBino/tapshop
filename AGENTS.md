# AGENTS.md

Instructions for AI coding agents (Claude, Codex, Cursor, etc.) working in this repo. Humans: see README.md.

## What this is

TapShop: a mobile-first link-in-bio storefront. Creators get a page at `/<handle>`, sell digital products through Stripe Checkout on their own connected account, collect leads, and share a Portfolio with brands.

## Stack

Next.js 15 (App Router, server actions) · React 19 · TypeScript (strict) · Tailwind CSS 4 · Postgres + Prisma 6 · Stripe Connect (direct charges) · Vercel Blob / S3 / local disk storage · Resend email · zod for validation.

## Commands

```bash
npm install              # also runs prisma generate
npm run dev              # http://localhost:3000
npm run lint             # eslint (next/core-web-vitals + next/typescript)
npx tsc --noEmit         # typecheck
npx prisma migrate dev --name <short_snake_name>   # after editing prisma/schema.prisma
```

There is no test suite. Before calling a change done, `npm run lint` and `npx tsc --noEmit` must both pass.

`npm run build` runs `prisma migrate deploy` (via `scripts/migrate.sh`), so it needs a reachable database. Don't run it just to check types.

## Project layout

- `src/app/[handle]/` is the public storefront; `[handle]/[productId]` shows product, page and portfolio views.
- `src/app/dashboard/` is the creator dashboard. `src/middleware.ts` guards it and redirects to `/login` without a session.
- `src/app/actions/` holds server actions (`"use server"`), one file per area.
- `src/app/api/` holds route handlers: Stripe webhook, uploads, file serving, downloads, lead export, link redirects (`go/[id]`).
- `src/components/` is shared UI. Interactive pieces are client components (`"use client"`).
- `src/lib/` is domain logic and helpers: `db.ts` (Prisma singleton), `auth.ts`, `env.ts`, `storage.ts`, `stripe.ts`, `design.ts`, and one file per feature (`avatar`, `banner`, `iconStyle`, `mediaKit`, `pages`, `affiliate`, ...).
- `prisma/schema.prisma` plus `prisma/migrations/` hold the database.

Import with the `@/` alias (`@/lib/db`, `@/components/...`).

## Conventions

- **Server actions** start with `requireCreator()` (or `requireAdmin()`), validate `FormData` with a zod schema, and return `FormState` (`{ error }`) for form errors. Finish with `revalidatePath` / `redirect`. Follow `src/app/actions/pages.ts`.
- **Ownership:** every query on creator data filters by `creatorId: creator.id`. Never trust an id from the client on its own. For uploaded file keys, use `ownKey()` from `src/lib/storage.ts`.
- **Env vars:** read them through `env` in `src/lib/env.ts`, not `process.env` directly. If you add one, also add it to `.env.example` with a comment.
- **JSON style columns** (`avatarStyle`, `socialLinks`, banner and icon styles, portfolio sections) always go through their `parse...()` helper in `src/lib/`, which fills in defaults. Keep the parsers tolerant of old or partial data.
- **Design options:** valid theme, font, button and layout values live in `src/lib/design.ts`. Add new options there, not inline.
- **Migrations:** never edit an existing migration. Add a new one, and give new columns defaults so existing rows keep working.
- **Mobile first:** storefront and dashboard UI must work at phone width before anything else.
- **Images:** plain `<img>` with `// eslint-disable-next-line @next/next/no-img-element` is the existing pattern for user uploads.
- Match the surrounding style: small focused files, named exports, few comments, and the ones that exist explain *why*.

## Naming gotcha: Portfolio = media kit

The feature is called **Portfolio** in the UI, but the code still uses `mediaKit` (`src/lib/mediaKit.ts`, `MediaKitBuilder`, `MediaKitView`, `actions/mediaKit.ts`, the `KIT_SLUG` / `OLD_KIT_SLUG` constants). `/dashboard/media-kit` permanently redirects to `/dashboard/portfolio`. Use "Portfolio" in anything users see. Don't rename the code unless asked.

## Studio (design studio + video editor)

- `/dashboard/studio` embeds a static HTML/JS editor in an iframe. Its files live in `vendor/tapshop-studio/` and are served only to signed-in creators by `src/app/dashboard/studio/assets/[...path]/route.ts` (allowlisted file names). Never move them into `public/`.
- It's classic-script code: keep the script order in `video.html` (text-catalog → studio-catalog → video → panel-layout → timeline-strips → color-picker → vault-picker → video-start → video-camera → video-gfx → video-gfx-more → video-reviews → video-captions → video-autosave → video-export, then the shared `tapshop-theme` css/js; `index.html` loads text-catalog → studio-catalog first too, and `gif-encoder.js` → `studio-social.js` → `studio-projects.js` → `studio-pages.js` after its inline scripts; `photo.html` order is under Photo Lab below) and don't convert it to modules. `vendor/**` is excluded from ESLint.
- The asset route scopes the editor's `localStorage` keys per creator; don't bypass it.
- The editor talks to the dashboard only through `postMessage`, version 1: `tapshop:export-ready` (PNG → Save to TapShop), `tapshop:open-vault`, `tapshop:vault-changed`, `tapshop:vault-save` (`items: [{blob, name, source}]`, optional `sell: true` opens Sell this for the first file once saved), editor → dashboard `tapshop:studio-ready` (`page: design|video`, sent once the page's scripts have run) and `tapshop:designs` (`items: [{id, name, w, h, thumb}]`, thumb an SVG data URL or null), and `tapshop:edit-video` (`item: {id, name}`, a design video's "Open in Video Editor"), and dashboard → editor `tapshop:vault-export-all`, `tapshop:list-designs` and `tapshop:vault-import` (`item: {id, name, kind, contentType}`, optional `target: {design: 'new' | <id>}` on the design page; the editor fetches the file itself by id). "Use in Studio" (`UseInStudio.tsx`) asks where a file goes; `StudioFrame.sendTo()` opens the other Studio page first when needed. Design elements of `type: 'video'` keep only a Vault id plus a poster frame: they play on the canvas (`foreignObject`, the same `<video>` is reused across redraws by its `vid`) and use the poster in thumbnails and exports. Catalog shapes are `type: 'shape'` elements (`shape` = an id in `SHAPES` in `index.html`, a path in a 100×100 box scaled to the element, optional `stroke` (border on/off), `outline` (width), `outlineColor`, `noFill`, `opacity`, and text: `text`, `font`, `textBold`, `textColor`, `textSize` (0 = fit to the shape's `TEXT_BOX` area)); rectangle and circle keep their old `rect`/`circle` types but get the same options. Shapes render as `<g data-i>` holding the shape and its text. Text elements also render as `<g data-i>` and take optional `align` (left/center/right/justify), `italic`, `underline`, `lineH`, `letter`, box `boxFill`/`boxOpacity`/`borderStyle` (`TX_BORDERS`)/`borderW`/`borderColor`/`pad`/`radius`, `effect` (`TX_EFFECTS`)/`fxColor`/`fxStr`, and `anim` (`TX_ANIMS`)/`animDur`/`animDelay`/`animLoop`; animations only play on the canvas (CSS classes added while drawing live), never in exports. `studio-catalog.js` holds the shapes (`STUDIO_SHAPES`), shape text areas, emoji stickers and word stickers used by both editors (index.html aliases them as `SHAPES`, `STICKERS`, …). In the video editor, shape tracks accept `shape: 'cat:<id>'` (catalog shape) or `'emoji:<char>'` (sticker) and the optional `borderOn`/`borderW`/`borderColor`/`lineStyle`, `opacity`, text inside (`inner`, `innerColor`, `innerFont`, `innerBold`, `innerItalic`, `innerAlign`, `innerSize`), `stickerEdge`; Dragging a text/shape track snaps to the frame's centre, thirds and edges and to other visible tracks (faint grid + pink guide, drawn only while not exporting; toggle `tapshop-video-snap`), and each track has ⇤ ↔ ⇥ ⤒ ↕ ⤓ position buttons (`vePlace`); text tracks accept `align`, `italic`, `underline`, `lineH`, `letter`, `opacity` and a box (`boxColor`, `boxOpacity`, `boxBorder`, `boxBorderW`, `boxBorderColor`, `boxPad`, `boxRadius`). Shapes, stickers and pictures can also take `effect` (`SHAPE_FX`, an SVG filter)/`fxColor`/`fxStr` and the same `anim` settings as text (the element's markup is wrapped in a `<g data-i>` carrying the animation class and filter); shape text adds `textAlign`/`textItalic`/`textUnderline`/`textLineH`/`textLetter`, and shape borders `lineStyle`. Any element can be `hidden` (drawn as an empty `<g display=none>`, so also left out of exports) or `locked` (`pointer-events=none` + `data-locked`, taps pass through; still selectable from the ☰ Layers panel, which lists elements front-most first and reorders `design.els` by drag). The picker opens as a popover inside any open modal dialog holding its input, so it shows and works in front of pop-ups; Design Studio and Video Editor see-through sliders go down to 0%; saved brand colours live in `tapshop-brand-colors` (shared by both editors). Text, shapes, rectangles and circles take optional `fillGrad` (`{to, angle}`, fades from `fill`; a `markup()` wrapper swaps the main fill for a per-item `linearGradient`). Video editor text and shape tracks take optional `gradTo`/`gradAngle` (a `paintStyledText()` wrapper swaps `color` for a canvas gradient sized to each line or shape). **★ Brand kit** (design studio) keeps brand colours, `tapshop-brand-fonts` (`{heading, body}`) and `tapshop-brand-logo` (`{src, w, h}`, a PNG data URL shrunk to 600 px) in localStorage. The design studio also loads `text-catalog.js` + `text-fonts.css`, so its font lists offer the Video Editor's `TapFont*` fonts (`MORE_FONTS`; `TX_FONTS`/`SHAPE_FONTS.includes` accept them); the stage uses the page's fonts, while PNG/SVG/video downloads embed the fonts they use as base64 `@font-face` (`embedFonts`, `withFontCss`). In the Video Editor, **★ Brand** adds the brand logo (a shape track with `shape: 'brand:logo'` keeping its own `logoSrc`/`logoAR`) or text in the brand fonts, and every font list also offers the basic system fonts. Template and project cards with animated items play on hover (computers) or while on screen (touch, IntersectionObserver), using `liveSvg()`. Dragging on empty canvas draws a box that selects everything it touches (swipe to select, feeds `multiSel`). Templates with `animated: true` (category `Animated`, `ANIMATED_TEMPLATES`, built with the `TPL` helpers; text `_cx` = centre x) are ready-made posts and stories whose items all animate. **Select several** (`#multiBtn`, or Shift+click) keeps a temporary `multiSel` list that `groupMembers()` returns, so its items move, resize, line up (`multiAlign`) and delete together without a `group` id; it isn't saved. Elements sharing a `group` id move, resize (proportionally, from the group box) and use the position buttons together; `boxOf()` returns the group box for members. **Video ↓** (`runVideoExport`) records the design in real time with MediaRecorder (MP4 where supported, else WebM): still runs are pre-rendered once, animated text is drawn each frame from its paused Web Animations state (`currentTime`), videos are drawn from the live canvas `<video>`s (with sound when unmuted). Moving an element snaps to canvas centre/thirds/edges and other elements (`snapMove`, toggle saved as `forma-snap`). - **Media Vault**: `VaultItem` rows point at private storage keys. Files are served only to their owner by `src/app/api/vault/[id]/route.ts` (non-media types always download; everything except inline video and audio gets `CSP: sandbox`, which would strip the cookie from the browser player's own fetch; it answers `Range` requests, which iPhones need to play video). Uploads reuse `uploadFile(…, "private")` and `addVaultItems` checks `ownKey`. Each creator gets `VAULT_QUOTA_BYTES` (`lib/vault.ts`) in total: `saveToVault` checks before uploading and `addVaultItems` enforces it (deleting the just-uploaded objects when over). Folders (`VaultFolder`) are one level deep; `VaultItem.folderId` is optional, and deleting a folder keeps its files (`SetNull`). Renaming a file (`renameVaultItem`) only changes the part before its ending (`splitFileName`), because the Studio and `vaultKind` recognise projects by their ending. Folder ids from the client go through `ownFolder()` in `actions/vault.ts`. Inside the editor, `vault-picker.js` lists items via `GET /api/vault` and downloads them with `/api/vault/<id>?raw=1` (streams instead of redirecting to S3, so the fetch stays same-origin). Its video rows show a frame grabbed in the browser (hidden `<video>` on the `?raw=1` URL, on-screen rows only, two at a time, stopped when the picker closes) and remembered in `tapshop-vault-video-thumbs` (latest 100).
- **Sell this** (`SellThis.tsx`, `sellVaultItem`): turns a Vault file into a published DIGITAL product on the main store, from the Vault, the Video Editor's top bar (exports first) or the Design Studio (PNG for still designs; designs that move ask video or GIF and run `runVideoExport` with `dataset.sell`, GIFs via `gif-encoder.js`, sized by `GIF_SIZES`). The product points at the Vault file's own private key, so `deleteVaultItem` keeps the stored file while any product uses it. Covers are a separate small public picture made in the browser; GIFs get a frame slider through `ImageDecoder` where the browser has it, and videos get one once the whole file has downloaded (`?raw=1` can't seek). Projects can't be sold.

Other pages live in `design.pages` with `null` in the current slot, and `design.page` is the current index; single-page designs have neither field. PDFs are built in the browser with no library, one JPEG per page (`designPdf`). Multi-page designs sell as a PDF and also go to the Vault as one. Video ↓ records the current page.
- **Social templates** (`studio-social.js`): design-studio templates at each platform's size (Instagram, TikTok, YouTube, Facebook, Pinterest, LinkedIn, X, Creator), built with the `TPL` helpers like the animated ones (`social: true`, own `make()` branch), listed first, with platform chips replacing the old category chips; the old basic "Social" templates are now "Simple".
- **Project management** (`studio-projects.js`): on the design studio's Projects page each card gets a ⋯ menu (Open, Rename, Duplicate, Delete) and a Select mode deletes several at once; changes are written straight back to `projects` / `forma-projects`.
- **Video start screen** (`video-start.js`): an overlay shown when the Video Editor opens. `video.html` keeps the page hidden (`ve-boot`) until its scripts have run, so the editor doesn't flash first. It sets the frame shape from the chosen platform, imports picked videos (main timeline, `fit: 'cover'` for non-16:9) then photos (3 s `brand:logo` picture tracks sized to cover the frame), and adds an optional template (`TEMPLATES`: text tracks whose size is a fraction of frame height and whose timing `at(D)` adapts to the video length). Vault imports and project restores close it; **⌂ Start** in the top bar reopens it.
- **Use camera** (`video-camera.js`, step 2 of the start screen): touch devices choose photo or video, then a `capture` file input opens the device's camera app; computers get a webcam screen (`getUserMedia` + MediaRecorder, MP4 where supported, else WebM; the iframe has `allow="camera; microphone"`). The Add a video box uses it too, video only (`only: 'video'`), and its clips go through `videoDialogImport`, picture-in-picture box included. Finished shots on the start screen go through `addFiles` flagged `camera`, and **Save to Vault** under the file list sends unsaved ones with one tap. Browser recordings may not state their length, so `loadAsset` runs `findDuration` first.
- **Auto captions** (`video-captions.js`, **✨ Captions** in the timeline bar): speech recognition runs in the browser (Whisper `_timestamped` models via transformers.js from jsDelivr, in a module Web Worker; models download from Hugging Face once and the browser caches them). Clip audio is decoded to 16 kHz mono per clip and word times are mapped onto the timeline (clip start + time / speed). Captions are one graphic track `type: 'captions'` with `words: [{w, s, e}]` (seconds from the track's offset) and `style` (presets in `PRESETS`: font, size as a fraction of frame height, `maxWords`, colours, `hl` none/color/box/reveal, outline, box, shadow, `anim`, `y`); it draws them itself after the other layers, so preview and export match, and replaces the track's strip options with the caption editor. If word timing isn't available it falls back to sentence timing spread over the words.
- **Graphics packs** (`video-gfx.js`, **🎬 Graphics** in the timeline bar): animated overlays (hooks, price tags, link in bio, ratings, subscribe button, progress bar, confetti… listed in `GFX`, grouped by `PACKS`). Each is one graphic track `type: 'gfx'` with `gfx` (the id), `x`/`y` (%), `scale`, `rotation`, colours `c1`–`c3`, `font` and the piece's own fields (`t1`, `t2`, `n`, …; old or missing fields fall back to nothing drawn, never an error). Pieces draw in units of 1% of the frame's short side around (x, y); `full: true` pieces use the whole frame. It wraps `draw()` (so preview and export match, drawn before captions), `renderGraphicTracks()` (the track's options become the graphic's editor) and `exportVideo()` (loads fonts first). A capture-phase pointer handler drags graphics on the preview before the text/shape handlers see the touch. The picker plays every card live. `window.veDrawGfx(ctx, track, seconds, w, h)` draws one, for reuse by future templates. `video-gfx-more.js` adds more packs (text effects, arrows and pointers, frames and transitions, and extra pieces for the others) through `window.veGfxAdd(packs, items)`, using the shared helpers in `window.VE_GFX_KIT`; put new graphics there or in a new file loaded the same way. Piece options: `brand: true` takes brand colours, `xy: true` shows position controls on a full-frame piece, `noOut` skips the fade at the end (transitions), `pv` is the picker preview size, `tags` are extra search words. The picker has a search box and only redraws cards on screen. Pieces may also have `open(track|null)` (the picker calls it instead of adding a blank track, e.g. to show a builder), `fix(track, key)` (runs after an option changes; return true to redraw the options, e.g. when the length changed), `prepare(track)` (a promise awaited before export) and `extra(track)` (more HTML in the track's options); `veGfxDefaults(id)` and `veGfxInsert(track)` let a builder make tracks.
- **Review showcase** (`video-reviews.js`, **⭐ Reviews** in the timeline bar, a banner on the start screen above the templates, and a card in the Reviews pack): affiliates paste, drop, choose or pick from the Vault screenshots of other people's reviews. It is one graphics track `gfx: 'reviews'` with `imgs: [{src, w, h, anim, badge}]` (JPEG data URLs, at most 1000×2000; empty `anim`/`badge` use the track's own), `layout` (one/stack/carousel/wall/scroll), `anim`, `badge` (stars/verified/heart/fire/count/glow/none), `bg` (dim/blur/color/none; blur is a shrink-and-stretch of the canvas, since Safari has no canvas `filter`), `per` (seconds per review), `t1` opening line (drawn with the `hook` graphic), `t2` ending line (the `linkbio` graphic, plus `confetti`) and `frame`. Its length follows the number of reviews (`lengthOf`). With no video on the timeline it starts with the colour background.
- **Video export** (`exportVideo`) first tries `veFastExport` (`video-export.js`): Mediabunny (`mediabunny.js`, loaded on first export; a bundle of v1.61.6 from github.com/Vanilagy/mediabunny, MPL-2.0, licence in `vendor/tapshop-studio-licenses/`) reads each file's frames and sound directly, `draw()` paints them through `paintVideo` (`v._frame`) one frame at a time at 30 fps, and the sound is mixed in an `OfflineAudioContext` (speed changes keep pitch). Picture and sound can't drift and the page may be hidden. MP4 with H.264 and AAC where the browser can encode them. If it returns false (no WebCodecs, or a file or format it can't handle) the older real-time path records with MediaRecorder in the first of `EXPORT_FORMATS` the browser supports. Anything new drawn from a `<video>` must go through `paintVideo`, and anything new that affects the sound must be added to `mixSound` too.
- **Save to Vault** in the Video Editor's top bar asks video or project; **Save project** and **Open project** ask device or Vault (all through `askChoice`, `#choiceDialog`). Video runs the normal export with `exportToVault` set, so `download` sends the finished file to the Vault instead of the device; project sends a packed project (`vePackProject` in `video-autosave.js`): one file with a `TAPSHOP1` start, the auto-save state as JSON and every clip it uses, still named `.tapshop.json` so the Vault treats it as a project. `restoreProject` opens these first and falls back to plain JSON projects. Device saves use the same packed file. The old plain `saveProject` is no longer called from the UI.
- **Video projects on the Studio Projects page** (`studio-projects.js`): lists `.tapshop.json` files from the Vault and the auto-save Recent videos. Cards link to `video.html#vault=<id>&name=…` or `#recent=<id>`, which `video-autosave.js` opens on load. Each has a ⋯ menu: Recent videos change IndexedDB directly (`changeRecent`, which never creates the database); Vault files use `PATCH`/`DELETE` on `/api/vault/<id>` and then `tapshop:vault-changed` so the dashboard refreshes. Vault projects have no Duplicate.
- **Auto-save** (`video-autosave.js`): every 3 s, if the project changed, saves clips, graphic/caption tracks, layer settings, frame shape, name, a thumbnail and the media files it uses to IndexedDB `tapshop-video-<creator scope>` (stores `projects` and `media`, keeps the 12 most recent). The scope comes from the asset route's localStorage prefix, so creators sharing a browser stay separate. The start screen's **Recent videos** has a ⋯ menu per card: Open (videos reload under their saved asset ids), Rename, Duplicate (copies the record and its media under a new id) and Delete; starting a new video from the start screen empties the timeline first (`veNewProject`).
- **TapShop look** (`tapshop-theme.css` + `tapshop-theme.js`, loaded last on both pages): restyles the editors with the dashboard palette and, inside the dashboard, follows the `tapshop_theme` cookie and hides the editors' own light/dark switch.
- **Collapse toggle shake** (`tapshop-theme.js`, `ts-shake` in `tapshop-theme.css`): the sidebar and tools toggles (`#sidebarToggle`, `#toolsToggle`) shake for a second the first time they show after the page loads, skipped when the device asks for reduced motion. The Video Editor and the dashboard have no collapse toggle.
- **Photo Lab** (`photo.html`, the photo editor; sidebar button under Video Studio, a format card on the Studio home, and **Edit in Photo Lab** in Use in Studio for pictures): script order text-catalog → color-picker → vault-picker → `photo-core.js` (image `doc` with `layers` (index 0 = bottom, each `{id, name, canvas, x, y, visible, opacity, blend, lockAlpha, text}`), compositing, zoom/pan, selection mask `doc.sel` (image-sized canvas, white = selected) with marching ants, undo history, layers/history panels, dialogs, menus) → `photo-adjust.js` (colour adjustments, filters, image/layer geometry through `affineLayer`) → `photo-tools.js` (toolbox, tool options saved in `tapshop-photo-tools`, brush and retouch engines, Edit actions, shortcuts) → `photo-io.js` (start screen, open/export, Vault, auto-save, the `MENUS` table) → `tapshop-theme.js`. **History rule:** a layer canvas or selection mask that history may hold is never drawn into; edits draw into a copy (`clone`) or a new canvas and swap it in, so `snap()` only keeps references. History drops old steps past `HIST_BYTES`. Pixel work is plain JS on ImageData (Safari's canvas `filter` isn't relied on); `adjust()` previews on a copy of big layers shrunk to about 1.2 MP (drawn through `preview.matrix`) and runs full size on OK; `clipToSel` keeps the result inside the selection. Text layers keep `text` (re-rendered by `renderText`) until a pixel edit clears it. Pictures larger than `MAX_AREA` are shrunk on open (phones have a 16 MP canvas limit). Auto-save keeps one image (layers as PNGs) in IndexedDB `tapshop-photo-<creator scope>`. Save to Vault and Sell this send a PNG of the flattened image with `tapshop:vault-save`; `vault-picker.js` reports this page as `page: 'photo'`.

## Payments and files (be careful here)

- Paid orders are marked paid both on the thank-you page and in the Stripe webhook. That path must stay **idempotent**, and the delivery email goes out exactly once.
- **Discount codes** (`lib/discounts.ts`, `/dashboard/discounts`): a code takes a percent or a fixed amount off one product or the whole store, with an optional use limit and last day. The price is worked out only in `startCheckout`; `previewCode` just shows it to the buyer. Stripe gets the lower price as `unit_amount`, not a Stripe coupon, so `markPaid` needs no changes. Uses are counted from orders (`usedOrders`): paid and refunded ones, plus unpaid ones from the last 35 minutes, which is why checkouts with a code close after 31. `startCheckout` locks the code row while it checks the limit and creates the order. A 100% code skips Stripe like a free product; prices that land between 0 and `STRIPE_MIN_CENTS` are refused. The affiliate page `extras.code` is a different thing: text the creator shows visitors.
- Paid files are private. They are only served through `/api/download/<token>` after the order is checked. Never give a paid file a public URL.
- Charges are direct charges on the creator's connected account. `ALLOW_PLATFORM_CHARGES` is for local testing only.

## Git and PRs

- Work on a branch and open a PR into `main`; don't push to `main` directly.
- Commit messages are short, plain English and describe what the user gets, e.g. "Let the portfolio video section hold several videos".
- Never commit `.env*` files (except `.env.example`), `/storage`, or secrets.
