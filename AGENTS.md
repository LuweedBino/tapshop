# AGENTS.md

Instructions for AI coding agents (Claude, Codex, Cursor, etc.) working in this repo. Humans: see README.md.

## What this is

TapShop: a mobile-first link-in-bio storefront. Creators get a page at `/<handle>`, sell digital products through Stripe Checkout on their own connected account, collect leads, and share a Portfolio with brands.

## Stack

Next.js 15 (App Router, server actions) · React 19 · TypeScript (strict) · Tailwind CSS 4 · Postgres + Prisma 6 · Stripe Connect (direct charges) · Vercel Blob / S3 / local disk storage · Resend email · zod for validation.

## Commands

```bash
npm install              # also runs prisma generate
npm run dev              # http://localhost:3000
npm run lint             # eslint (next/core-web-vitals + next/typescript)
npx tsc --noEmit         # typecheck
npx prisma migrate dev --name <short_snake_name>   # after editing prisma/schema.prisma
```

There is no test suite. Before calling a change done, `npm run lint` and `npx tsc --noEmit` must both pass.

`npm run build` runs `prisma migrate deploy` (via `scripts/migrate.sh`), so it needs a reachable database. Don't run it just to check types.

## Project layout

- `src/app/[handle]/` is the public storefront; `[handle]/[productId]` shows product, page and portfolio views.
- `src/app/dashboard/` is the creator dashboard. `src/middleware.ts` guards it and redirects to `/login` without a session.
- `src/app/actions/` holds server actions (`"use server"`), one file per area.
- `src/app/api/` holds route handlers: Stripe webhook, uploads, file serving, downloads, lead export, link redirects (`go/[id]`).
- `src/components/` is shared UI. Interactive pieces are client components (`"use client"`).
- `src/lib/` is domain logic and helpers: `db.ts` (Prisma singleton), `auth.ts`, `env.ts`, `storage.ts`, `stripe.ts`, `design.ts`, and one file per feature (`avatar`, `banner`, `iconStyle`, `mediaKit`, `pages`, `affiliate`, ...).
- `prisma/schema.prisma` plus `prisma/migrations/` hold the database.

Import with the `@/` alias (`@/lib/db`, `@/components/...`).

## Conventions

- **Server actions** start with `requireCreator()` (or `requireAdmin()`), validate `FormData` with a zod schema, and return `FormState` (`{ error }`) for form errors. Finish with `revalidatePath` / `redirect`. Follow `src/app/actions/pages.ts`.
- **Ownership:** every query on creator data filters by `creatorId: creator.id`. Never trust an id from the client on its own. For uploaded file keys, use `ownKey()` from `src/lib/storage.ts`.
- **Env vars:** read them through `env` in `src/lib/env.ts`, not `process.env` directly. If you add one, also add it to `.env.example` with a comment.
- **JSON style columns** (`avatarStyle`, `socialLinks`, banner and icon styles, portfolio sections) always go through their `parse...()` helper in `src/lib/`, which fills in defaults. Keep the parsers tolerant of old or partial data.
- **Design options:** valid theme, font, button and layout values live in `src/lib/design.ts`. Add new options there, not inline.
- **Migrations:** never edit an existing migration. Add a new one, and give new columns defaults so existing rows keep working.
- **Mobile first:** storefront and dashboard UI must work at phone width before anything else.
- **Images:** plain `<img>` with `// eslint-disable-next-line @next/next/no-img-element` is the existing pattern for user uploads.
- Match the surrounding style: small focused files, named exports, few comments, and the ones that exist explain *why*.

## Naming gotcha: Portfolio = media kit

The feature is called **Portfolio** in the UI, but the code still uses `mediaKit` (`src/lib/mediaKit.ts`, `MediaKitBuilder`, `MediaKitView`, `actions/mediaKit.ts`, the `KIT_SLUG` / `OLD_KIT_SLUG` constants). `/dashboard/media-kit` permanently redirects to `/dashboard/portfolio`. Use "Portfolio" in anything users see. Don't rename the code unless asked.

In the Video Editor, **★ Brand** adds the brand logo (a shape track with `shape: 'brand:logo'` keeping its own `logoSrc`/`logoAR`) or text in the brand fonts, and every font list also offers the basic system fonts. Template and project cards with animated items play on hover (computers) or while on screen (touch, IntersectionObserver), using `liveSvg()`. Dragging on empty canvas draws a box that selects everything it touches (swipe to select, feeds `multiSel`). Templates with `animated: true` (category `Animated`, `ANIMATED_TEMPLATES`, built with the `TPL` helpers; text `_cx` = centre x) are ready-made posts and stories whose items all animate. **Select several** (`#multiBtn`, or Shift+click) keeps a temporary `multiSel` list that `groupMembers()` returns, so its items move, resize, line up (`multiAlign`) and delete together without a `group` id; it isn't saved. Elements sharing a `group` id move, resize (proportionally, from the group box) and use the position buttons together; `boxOf()` returns the group box for members. **Video ↓** (`runVideoExport`) records the design in real time with MediaRecorder (MP4 where supported, else WebM): still runs are pre-rendered once, animated text is drawn each frame from its paused Web Animations state (`currentTime`), videos are drawn from the live canvas `<video>`s (with sound when unmuted). - **Media Vault**: `VaultItem` rows point at private storage keys. Files are served only to their owner by `src/app/api/vault/[id]/route.ts` (non-media types always download; everything except inline video and audio gets `CSP: sandbox`, which would strip the cookie from the browser player's own fetch; it answers `Range` requests, which iPhones need to play video). Uploads reuse `uploadFile(…, "private")` and `addVaultItems` checks `ownKey`. Each creator gets `VAULT_QUOTA_BYTES` (`lib/vault.ts`) in total: `saveToVault` checks before uploading and `addVaultItems` enforces it (deleting the just-uploaded objects when over). Folders (`VaultFolder`) are one level deep; `VaultItem.folderId` is optional, and deleting a folder keeps its files (`SetNull`). Renaming a file (`renameVaultItem`) only changes the part before its ending (`splitFileName`), because the Studio and `vaultKind` recognise projects by their ending. Folder ids from the client go through `ownFolder()` in `actions/vault.ts`. Inside the editor, `vault-picker.js` lists items via `GET /api/vault` and downloads them with `/api/vault/<id>?raw=1` (streams instead of redirecting to S3, so the fetch stays same-origin). Its video rows show a frame grabbed in the browser (hidden `<video>` on the `?raw=1` URL, on-screen rows only, two at a time, stopped when the picker closes) and remembered in `tapshop-vault-video-thumbs` (latest 100).
- **Sell this** (`SellThis.tsx`, `sellVaultItem`): turns a Vault file into a published DIGITAL product on the main store, from the Vault, the Video Editor's top bar (exports first) or the Design Studio (PNG for still designs; designs that move ask video or GIF and run `runVideoExport` with `dataset.sell`, GIFs via `gif-encoder.js`, sized by `GIF_SIZES`). The product points at the Vault file's own private key, so `deleteVaultItem` keeps the stored file while any product uses it. Covers are a separate small public picture made in the browser; GIFs get a frame slider through `ImageDecoder` where the browser has it, and videos get one once the whole file has downloaded (`?raw=1` can't seek). Projects can't be sold.

- **Video start screen** (`video-start.js`): an overlay shown when the Video Editor opens. `video.html` keeps the page hidden (`ve-boot`) until its scripts have run, so the editor doesn't flash first. It sets the frame shape from the chosen platform, imports picked videos (main timeline, `fit: 'cover'` for non-16:9) then photos (3 s `brand:logo` picture tracks sized to cover the frame), and adds an optional template (`TEMPLATES`: text tracks whose size is a fraction of frame height and whose timing `at(D)` adapts to the video length). Vault imports and project restores close it; **⌂ Start** in the top bar reopens it. The chosen platform card fills in with a pink ring and ✓ (`aria-pressed`). Step 3's templates (`#vsTpls`) are two rows that scroll sideways together as one strip (`grid-auto-flow: column`). Its intro (`.vs-lead`, which other scripts use as an anchor) is a card of three paths (`.vs-paths`; a second after opening and then every 9 seconds, a diagonal shimmer in the text colour sweeps across their icons, bottom one first, `vs-shimmer`): quick makers (scrolls to `#vsQuick`), the 1-2-3 steps (scrolls to step 1) and Video Editor (clicks `#vsBlank`), with a quiet "or continue with a recent video" link under it (`#vsRecentLink`, shown only while `#vsRecentSec` is, scrolls there).
- **Use camera** (`video-camera.js`, step 2 of the start screen): touch devices choose photo or video, then a `capture` file input opens the device's camera app; computers get a webcam screen (`getUserMedia` + MediaRecorder, MP4 where supported, else WebM; the iframe has `allow="camera; microphone"`). The Add a video box uses it too, video only (`only: 'video'`), and its clips go through `videoDialogImport`, picture-in-picture box included. Finished shots on the start screen go through `addFiles` flagged `camera`, and **Save to Vault** under the file list sends unsaved ones with one tap. Browser recordings may not state their length, so `loadAsset` runs `findDuration` first.
- **Auto captions** (`video-captions.js`, **✨ Captions** in the timeline bar): speech recognition runs in the browser (Whisper `_timestamped` models via transformers.js from jsDelivr, in a module Web Worker; models download from Hugging Face once and the browser caches them). Clip audio is decoded to 16 kHz mono per clip and word times are mapped onto the timeline (clip start + time / speed). Captions are one graphic track `type: 'captions'` with `words: [{w, s, e}]` (seconds from the track's offset) and `style` (presets in `PRESETS`: font, size as a fraction of frame height, `maxWords`, colours, `hl` none/color/box/reveal, outline, box, shadow, `anim`, `y`); it draws them itself after the other layers, so preview and export match, and replaces the track's strip options with the caption editor. If word timing isn't available it falls back to sentence timing spread over the words.
- **Graphics packs** (`video-gfx.js`, **🎬 Graphics** in the timeline bar): animated overlays (hooks, price tags, link in bio, ratings, subscribe button, progress bar, confetti… listed in `GFX`, grouped by `PACKS`). Each is one graphic track `type: 'gfx'` with `gfx` (the id), `x`/`y` (%), `scale`, `rotation`, colours `c1`–`c3`, `font` and the piece's own fields (`t1`, `t2`, `n`, …; old or missing fields fall back to nothing drawn, never an error). Pieces draw in units of 1% of the frame's short side around (x, y); `full: true` pieces use the whole frame. It wraps `draw()` (so preview and export match, drawn before captions), `renderGraphicTracks()` (the track's options become the graphic's editor) and `exportVideo()` (loads fonts first). A capture-phase pointer handler drags graphics on the preview before the text/shape handlers see the touch. The picker plays every card live. `window.veDrawGfx(ctx, track, seconds, w, h)` draws one, for reuse by future templates. `video-gfx-more.js` adds more packs (text effects, arrows and pointers, frames and transitions, and extra pieces for the others) through `window.veGfxAdd(packs, items)`, using the shared helpers in `window.VE_GFX_KIT`; put new graphics there or in a new file loaded the same way. Piece options: `brand: true` takes brand colours, `xy: true` shows position controls on a full-frame piece, `noOut` skips the fade at the end (transitions), `pv` is the picker preview size, `tags` are extra search words. The picker has a search box and only redraws cards on screen. Pieces may also have `open(track|null)` (the picker calls it instead of adding a blank track, e.g. to show a builder), `fix(track, key)` (runs after an option changes; return true to redraw the options, e.g. when the length changed), `prepare(track)` (a promise awaited before export) and `extra(track)` (more HTML in the track's options); `veGfxDefaults(id)` and `veGfxInsert(track)` let a builder make tracks.
- **Review showcase** (`video-reviews.js`, **⭐ Reviews** in the timeline bar, a banner at the top of the start screen, and a card in the Reviews pack): affiliates paste, drop, choose or pick from the Vault screenshots of other people's reviews. It is one graphics track `gfx: 'reviews'` with `imgs: [{src, w, h, anim, badge}]` (JPEG data URLs, at most 1000×2000; empty `anim`/`badge` use the track's own), `layout` (one/stack/carousel/wall/scroll), `anim`, `badge` (stars/verified/heart/fire/count/glow/none), `bg` (dim/blur/color/none; blur is a shrink-and-stretch of the canvas, since Safari has no canvas `filter`), `per` (seconds per review), `t1` opening line (drawn with the `hook` graphic), `t2` ending line (the `linkbio` graphic, plus `confetti`) and `frame`. Its length follows the number of reviews (`lengthOf`). With no video on the timeline it starts with the colour background.
- **B-roll builder** (`video-broll.js`, **🎞️ B-roll** in the timeline bar and a banner on the start screen; `video-broll.js` keeps both quick-maker banners in `#vsQuick`, right under the start screen's intro and above Recent videos): the creator adds clips (device, Vault or the timeline's own clips), picks a story template (`TEMPLATES`: Hook → Problem → Solution → CTA, Before → After, 3 reasons, Unboxing, How to use it, Myth vs truth, Day in my life, This vs that, POV / storytime, Honest review; each part has on-screen text, a style, `look` weights over `LOOKS` and a `say` word regex), and a module worker (transformers.js from jsDelivr) looks at three frames per clip with CLIP zero-shot (`Xenova/clip-vit-base-patch32`) and listens to the first 28 s with Whisper tiny (same model id as caption Fast mode, so the cache is shared). `arrange()` gives every part its best clip first, then the rest to their best part, with a small pull towards the order they were added; if the AI can't load, the clips keep their order. The review step lets the creator move clips between parts and edit each part's words. Building replaces the current video (`veNewProject`, the old one stays in Recent videos): talking clips keep their whole speech, other clips are cut to whole beats, one text track per part, and a beat made in the browser (`makeBeat`, WebAudio in an `OfflineAudioContext`, moods in `MOODS`, saved as a WAV) goes on its own audio track, quieter when someone talks.
- **Timeline toolbar** (`video-toolbar.js`, loaded after every script that adds buttons): sorts the `.timebar` buttons into one scrollable row of labelled sections (Add, Create, Edit, View; unknown buttons go to Create, and a MutationObserver sorts buttons added later), and moves the "Timeline" title into the corner left of the ruler (`.tl-title`, placed from the ruler's offsets). Find toolbar buttons with `.timebar button` (they're nested now), not `.timebar>button`. Each button is restyled like phone quick settings (`.tb-btn`: a round `.tb-ic` icon taken from the label's leading emoji/symbol, the name in `.tb-tx` below; names wider than the button scroll back and forth via `.tb-tx.run`); the button's `aria-label`/`title` keep the name, and a button whose text another script replaces is rebuilt. `tapshop-theme.css` skips `.tb-btn` in its generic button rules. Track names left of the lanes sit in a narrow column (68 px + 8 px row padding; `LANE_START` in `timeline-strips.js` and the ruler's left margin must match it), and names too long for it scroll the same way (`.strip-name.run`, also in `video-toolbar.js`).
- **Top bar** (`video-topbar.js`, loaded after every script that adds top-bar buttons): rebuilds `header.top` into two rows. Both rows are the same thin height (40 px, 30 px controls). Row 1: ← Studio, ⌂ Start and the name field (`#projectName` in a pill with a pencil, dashed until focused, a pink "tap to name it" inside it while it's Untitled). Row 2: sections with small inline labels Project (Open, Save, Reset layout) and Share (Save to Vault, Sell this, Export); unknown buttons go to a More section. - **Video export** (`exportVideo`) first tries `veFastExport` (`video-export.js`): Mediabunny (`mediabunny.js`, loaded on first export; a bundle of v1.61.6 from github.com/Vanilagy/mediabunny, MPL-2.0, licence in `vendor/tapshop-studio-licenses/`) reads each file's frames and sound directly, `draw()` paints them through `paintVideo` (`v._frame`) one frame at a time at 30 fps, and the sound is mixed in an `OfflineAudioContext` (speed changes keep pitch). Picture and sound can't drift and the page may be hidden. MP4 with H.264 and AAC where the browser can encode them. If it returns false (no WebCodecs, or a file or format it can't handle) the older real-time path records with MediaRecorder in the first of `EXPORT_FORMATS` the browser supports. Anything new drawn from a `<video>` must go through `paintVideo`, and anything new that affects the sound must be added to `mixSound` too.

Video runs the normal export with `exportToVault` set, so `download` sends the finished file to the Vault instead of the device; project sends a packed project (`vePackProject` in `video-autosave.js`): one file with a `TAPSHOP1` start, the auto-save state as JSON and every clip it uses, still named `.tapshop.json` so the Vault treats it as a project. `restoreProject` opens these first and falls back to plain JSON projects. Rows exist only for their strips, so a row left empty goes away. A pink note at the top of the screen, away from the timeline (`stripTip`), explains this for 9 s the first 3 times the editor is used, only once the editor is showing with strips on the timeline (`editorWithStrips()`: page loaded, start screen closed; it goes away if the start screen opens) (✕ ends it); there's also a Quick tip.
  - **Main clips ↔ video layers** (`clipToLayer`/`layerToClip`, end of `timeline-strips.js`): a main video clip dragged up or down off the main row becomes a video layer (picture in picture, `scale` 100 so it looks the same) at the same time and part of the file (`mainDrop`: over the middle of a video-layer row it joins that row, else a new layer, line labelled "New video layer"); a video layer dropped on the main row goes back into the main video at its time (or the first free spot after it). Other main clips keep their places (offsets fixed first), so a gap is left for its 🗑. The layer gets its own `<video>` for the clip's file, loaded directly (not `loadTrackMedia`, which rejects phone recordings whose length isn't known until later); if it still fails, Undo rolls everything back and nothing is left behind. A drag only switches to up/down after 14 px with a mouse, 34 px by touch (44 px for main clips), and only when it's mostly vertical, so a sideways drag on a phone doesn't jump tracks. The strip note's counter key is `tapshop-strip-tip2` (reset once because it had been used up on the start screen).
  - **🗑 Empty space** (`addGapBins`/`closeGap`, end of `timeline-strips.js`): every row shows a small dashed 🗑 in each gap of 0.15 s or more between two of its strips. On the main video row it deletes that time from the whole video (`rippleGap(A, d, true)`: everything after moves left; with `keep`, things inside the gap move to its start instead of being removed); on other rows only that row's later strips move. Dragging a strip over the middle of a row of another kind makes a new track above or below it (by which half).
  - **Ripple delete** (end of `timeline-strips.js`, `rippleGap(A, d)`): deleting a main-row clip closes the gap and moves everything on the other rows with it: later main clips with their own `offset`, graphic tracks (text, stickers, effects; captions also drop and shift their `words`), and extra tracks (video layers, audio, music via `start`/`end`/`speed`). Items only on the deleted clip are removed, items crossing it get shorter. When there are captions, the toast points to **🔄 Redo captions** (`capRedo(id)` in `video-captions.js`, two `.cap-redo` buttons in the Captions strip: one at the top next to ★ Save my style and Delete captions, one in the Timing row): it re-listens to the timeline as it is now (cloud AI first if on and not turned off in the B-roll builder, else `listenAll` on the device), drops um/uh, and replaces the Captions track keeping its style; Undo-able. The snapshot taken before the delete covers it all, so one Undo restores everything.
  - The first time the editor shows (start screen closed), the timeline toolbar glides to its far end and back (`video-toolbar.js`, scroll-snap off during the glide). Skipped when it all fits, for reduced motion, and stopped by any touch or wheel on the bar.
  - Chrome on Android lets idle videos "sleep" (`readyState` < 2, so `draw()` skipped them and the preview went black). `draw()` calls `wakeVideo(v, t)` for a sleeping video while paused: a short muted `play()`, then back to the frame and a redraw (`v._waking` guards it).
- **Voiceover recorder** (`video-voiceover.js`, **🎙️ Voiceover** in the timeline bar, `window.veVoiceover(script?)`): a teleprompter dialog. Scenes come from `tapshop:voiceover-script` (the dashboard's **✨ AI Script Writer**, `ScriptGeneratorDrawer.tsx` + `/api/generate-script`, Gemini) or ✏️ Edit script (one line per scene). 3-2-1 countdown, then MediaRecorder on the mic; the highlighted line moves on after the scene's planned seconds (or ~2.5 words/s) divided by the prompter Speed (0.5–2×), or only on Next scene / → / tapping a line when "Only move when I tap Next scene" is on (text size, speed and that switch are kept in `tapshop-vo-prefs`). On phones (≤700px) the dialog fills the screen: only the script scrolls, settings fold away while recording, and the buttons stay at the bottom; and the real start of each scene is kept in `S.marks`. The take is decoded and saved as a mono WAV (browser recordings may not state their length) and added at the playhead as an audio track with `voiceover: true`, `duck: false`, no fades, and `veAutoBeat` skipped, so speech detection treats it as the voice. Optionally each scene's `onScreenText` becomes a text track at its mark. A message from the dashboard hides the start screen first.
- **Build My Video With AI** (`video-agent.js`, `window.veBuildMyVideo()`; the dashboard's gold button above the Studio sends `tapshop:open-agent`, plus **🪄 Build My Video** in the timeline bar and the first card in the start screen's quick makers): a guided maker in 7 steps (About, Story, Script, Footage, Voice, Graphics, Build), full screen on phones like the voiceover recorder. The scene plan `S.scenes` (`{type, secs, say, text, shot, anim, sfx}`) is its backbone. Story types are the 24 of `STORY_TYPES` in `src/types/script.ts` (plus `AUTO`; the agent keeps its own copy of ids, labels and a default music style each, so keep both lists in step). The script comes from `/api/generate-script` (streamed NDJSON, with `platform` and `textOnly`) or the creator's own lines; footage is added or filmed per scene (`VideoCamera`); the voiceover is recorded through `veVoiceover(script, {onTake})`, whose scene marks set each scene's start. Building replaces the current video (`veNewProject`) with ordinary clips (main clips placed by `offset`, trimmed or slowed to fit, muted under a voiceover), a `voiceover` audio track, one text track per scene (animation from `TEXT_ANIMATIONS`, brand fonts/colours when a brand kit exists), a tied sound effect each (`TapSFX.add` with `forId`), music (`veMakeBeat` + `veMusicTrackMeta`) and captions (the voice take as a temporary asset through `veClipWords` + `vePlaceCaptions`, or `veAutoCaptions` for talking clips). Choices and words are saved in `tapshop-agent-draft`; clips and the take are in memory only.

## Payments and files (be careful here)

- Paid orders are marked paid both on the thank-you page and in the Stripe webhook. That path must stay **idempotent**, and the delivery email goes out exactly once.
- **Discount codes** (`lib/discounts.ts`, `/dashboard/discounts`): a code takes a percent or a fixed amount off one product or the whole store, with an optional use limit and last day. The price is worked out only in `startCheckout`; `previewCode` just shows it to the buyer. Stripe gets the lower price as `unit_amount`, not a Stripe coupon, so `markPaid` needs no changes. Uses are counted from orders (`usedOrders`): paid and refunded ones, plus unpaid ones from the last 35 minutes, which is why checkouts with a code close after 31. `startCheckout` locks the code row while it checks the limit and creates the order. A 100% code skips Stripe like a free product; prices that land between 0 and `STRIPE_MIN_CENTS` are refused. The affiliate page `extras.code` is a different thing: text the creator shows visitors.
- Paid files are private. They are only served through `/api/download/<token>` after the order is checked. Never give a paid file a public URL.
- Charges are direct charges on the creator's connected account. `ALLOW_PLATFORM_CHARGES` is for local testing only.
