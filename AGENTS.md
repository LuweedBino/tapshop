# AGENTS.md

Instructions for AI coding agents (Claude, Codex, Cursor, etc.) working in this repo. Humans: see README.md.

## What this is

TapShopUGC: a mobile-first link-in-bio storefront. Creators get a page at `/<handle>`, sell digital products through Stripe Checkout on their own connected account, collect leads, and share a Portfolio with brands.

## Stack

Next.js 15 (App Router, server actions) · React 19 · TypeScript (strict) · Tailwind CSS 4 · Postgres + Prisma 6 · Stripe Connect (direct charges) · Vercel Blob / S3 / local disk storage · Resend email · zod for validation.

## Commands

```bash
npm install              # also runs prisma generate
npm run dev              # http://localhost:3000
npm run lint             # eslint (next/core-web-vitals + next/typescript)
npx tsc --noEmit         # typecheck
npx prisma migrate dev --name <short_snake_name>   # after editing prisma/schema.prisma
```

There is no test suite. Before calling a change done, `npm run lint` and `npx tsc --noEmit` must both pass.

`npm run build` runs `prisma migrate deploy` (via `scripts/migrate.sh`), so it needs a reachable database. Don't run it just to check types.

## Project layout

- `src/app/[handle]/` is the public storefront; `[handle]/[productId]` shows product, page and portfolio views.
- `src/app/dashboard/` is the creator dashboard. `src/middleware.ts` guards it and redirects to `/login` without a session.
- `src/app/actions/` holds server actions (`"use server"`), one file per area.
- `src/app/api/` holds route handlers: Stripe webhook, uploads, file serving, downloads, lead export, link redirects (`go/[id]`).
- `src/components/` is shared UI. Interactive pieces are client components (`"use client"`).
- `src/lib/` is domain logic and helpers: `db.ts` (Prisma singleton), `auth.ts`, `env.ts`, `storage.ts`, `stripe.ts`, `design.ts`, and one file per feature (`avatar`, `banner`, `iconStyle`, `mediaKit`, `pages`, `affiliate`, ...).
- `prisma/schema.prisma` plus `prisma/migrations/` hold the database.

Import with the `@/` alias (`@/lib/db`, `@/components/...`).

## Conventions

- **Server actions** start with `requireCreator()` (or `requireAdmin()`), validate `FormData` with a zod schema, and return `FormState` (`{ error }`) for form errors. Finish with `revalidatePath` / `redirect`. Follow `src/app/actions/pages.ts`.
- **Ownership:** every query on creator data filters by `creatorId: creator.id`. Never trust an id from the client on its own. For uploaded file keys, use `ownKey()` from `src/lib/storage.ts`.
- **Env vars:** read them through `env` in `src/lib/env.ts`, not `process.env` directly. If you add one, also add it to `.env.example` with a comment.
- **JSON style columns** (`avatarStyle`, `socialLinks`, banner and icon styles, portfolio sections) always go through their `parse...()` helper in `src/lib/`, which fills in defaults. Keep the parsers tolerant of old or partial data.
- **Design options:** valid theme, font, button and layout values live in `src/lib/design.ts`. Add new options there, not inline.
- **Migrations:** never edit an existing migration. Add a new one, and give new columns defaults so existing rows keep working.
- **Mobile first:** storefront and dashboard UI must work at phone width before anything else.
- **Images:** plain `<img>` with `// eslint-disable-next-line @next/next/no-img-element` is the existing pattern for user uploads.
- Match the surrounding style: small focused files, named exports, few comments, and the ones that exist explain *why*.

## Page builder (extra store pages)

Extra pages (`Page`, `/<handle>/<slug>`) are designed in the page builder (`/dashboard/products/pages/[id]`, `PageBuilder.tsx`; a new page is created with `PageForm` and then opens there). Everything except name, link and description lives in `Page.design` and always goes through `parsePageDesign()` (`lib/pageDesign.ts`): `look` (`custom: false` = the store's own theme/colors/font/buttons/layout), `background` (theme, color, gradient, or an uploaded image with `dim`), `header` (banner same as store / its own via `BannerEditor` / none, photo, name, socials, title size, align), `blocks` (ordered sections: products, heading, text, image, gallery, video, button, testimonial, FAQ, countdown, divider, space; add new types to `BLOCK_TYPES`, `Block`, `newBlock`, `parseBlock`, `BlockView` and `BlockFields`) and `footer` (note, links, socials, "Made with TapShopUGC"). `PageView.tsx` draws a page for both the public route and the builder's live preview, so they always match. `savePageBuilder` checks every picture with `ownKey(…, "public")` (`pageDesignKeys`) and normalizes links. Only the creator fields the page shows are passed to the builder (never the whole Creator).

## Naming gotcha: Portfolio = media kit

The feature is called **Portfolio** in the UI, but the code still uses `mediaKit` (`src/lib/mediaKit.ts`, `MediaKitBuilder`, `MediaKitView`, `actions/mediaKit.ts`, the `KIT_SLUG` / `OLD_KIT_SLUG` constants). `/dashboard/media-kit` permanently redirects to `/dashboard/portfolio`. Use "Portfolio" in anything users see. Don't rename the code unless asked.

In the Video Editor, **★ Brand** adds the brand logo (a shape track with `shape: 'brand:logo'` keeping its own `logoSrc`/`logoAR`) or text in the brand fonts, and every font list also offers the basic system fonts. Template and project cards with animated items play on hover (computers) or while on screen (touch, IntersectionObserver), using `liveSvg()`. - **Video start screen** (`video-start.js`): an overlay shown when the Video Editor opens. `video.html` keeps the page hidden (`ve-boot`) until its scripts have run, so the editor doesn't flash first. It sets the frame shape from the chosen platform, imports picked videos (main timeline, `fit: 'cover'` for non-16:9) then photos (3 s `brand:logo` picture tracks sized to cover the frame), and adds an optional template (`TEMPLATES`: text tracks whose size is a fraction of frame height and whose timing `at(D)` adapts to the video length). Vault imports and project restores close it; **⌂ Start** in the top bar reopens it. The chosen platform card fills in with a pink ring and ✓ (`aria-pressed`). Step 3's templates (`#vsTpls`) are two rows that scroll sideways together as one strip (`grid-auto-flow: column`). Its intro (`.vs-lead`, which other scripts use as an anchor) is a card of three paths (`.vs-paths`; a second after opening and then every 9 seconds, a diagonal shimmer in the text colour sweeps across their icons, bottom one first, `vs-shimmer`): quick makers (scrolls to `#vsQuick`), the 1-2-3 steps (scrolls to step 1) and Video Editor (clicks `#vsBlank`), with a quiet "or continue with a recent video" link under it (`#vsRecentLink`, shown only while `#vsRecentSec` is, scrolls there).
- **Use camera** (`video-camera.js`, step 2 of the start screen): touch devices choose photo or video, then a `capture` file input opens the device's camera app; computers get a webcam screen (`getUserMedia` + MediaRecorder, MP4 where supported, else WebM; the iframe has `allow="camera; microphone"`). `open()` also takes `inApp` (the webcam screen on touch screens too), `prompt` (text over the picture, timer towards `secs`) and `facing` (starting camera). The Add a video box uses it too, video only (`only: 'video'`), and its clips go through `videoDialogImport`, picture-in-picture box included. Finished shots on the start screen go through `addFiles` flagged `camera`, and **Save to Vault** under the file list sends unsaved ones with one tap. Browser recordings may not state their length, so `loadAsset` runs `findDuration` first.
- **Auto captions** (`video-captions.js`, **✨ Captions** in the timeline bar): speech recognition runs in the browser (Whisper `_timestamped` models via transformers.js from jsDelivr, in a module Web Worker; models download from Hugging Face once and the browser caches them). Clip audio is decoded to 16 kHz mono per clip and word times are mapped onto the timeline (clip start + time / speed). Muted clips (`muted` or volume 0, e.g. under a voiceover) are skipped, and audio tracks that carry a voice (`voiceTracks()`: `voiceover`, or any audio that isn't music (`bpm`/`musicKey`) or a sound effect) are listened to at their place too, so captions follow a recorded voiceover. Whisper's no-speech markers (`[BLANK_AUDIO]`, `[Music]`, `(silence)`, ♪…) are dropped (`NOT_SPEECH` in `toWords`). Captions are one graphic track `type: 'captions'` with `words: [{w, s, e}]` (seconds from the track's offset) and `style` (presets in `PRESETS`: font, size as a fraction of frame height, `maxWords`, colours, `hl` none/color/box/reveal, outline, box, shadow, `anim`, `y`); it draws them itself after the other layers, so preview and export match, and replaces the track's strip options with the caption editor. If word timing isn't available it falls back to sentence timing spread over the words.
- **Graphics packs** (`video-gfx.js`, **🎬 Graphics** in the timeline bar): animated overlays (hooks, price tags, link in bio, ratings, subscribe button, progress bar, confetti… listed in `GFX`, grouped by `PACKS`). Each is one graphic track `type: 'gfx'` with `gfx` (the id), `x`/`y` (%), `scale`, `rotation`, colours `c1`–`c3`, `font` and the piece's own fields (`t1`, `t2`, `n`, …; old or missing fields fall back to nothing drawn, never an error). Pieces draw in units of 1% of the frame's short side around (x, y); `full: true` pieces use the whole frame. It wraps `draw()` (so preview and export match, drawn before captions), `renderGraphicTracks()` (the track's options become the graphic's editor) and `exportVideo()` (loads fonts first). A capture-phase pointer handler drags graphics on the preview before the text/shape handlers see the touch. The picker plays every card live. `window.veDrawGfx(ctx, track, seconds, w, h)` draws one, for reuse by future templates. `video-gfx-more.js` adds more packs (text effects, arrows and pointers, frames and transitions, and extra pieces for the others) through `window.veGfxAdd(packs, items)`, using the shared helpers in `window.VE_GFX_KIT`; put new graphics there or in a new file loaded the same way. Piece options: `brand: true` takes brand colours, `xy: true` shows position controls on a full-frame piece, `noOut` skips the fade at the end (transitions), `pv` is the picker preview size, `tags` are extra search words. The picker has a search box and only redraws cards on screen. Pieces may also have `open(track|null)` (the picker calls it instead of adding a blank track, e.g. to show a builder), `fix(track, key)` (runs after an option changes; return true to redraw the options, e.g. when the length changed), `prepare(track)` (a promise awaited before export) and `extra(track)` (more HTML in the track's options); `veGfxDefaults(id)` and `veGfxInsert(track)` let a builder make tracks.
- **Review showcase** (`video-reviews.js`, **⭐ Reviews** in the timeline bar, a banner at the top of the start screen, and a card in the Reviews pack): affiliates paste, drop, choose or pick from the Vault screenshots of other people's reviews. It is one graphics track `gfx: 'reviews'` with `imgs: [{src, w, h, anim, badge}]` (JPEG data URLs, at most 1000×2000; empty `anim`/`badge` use the track's own), `layout` (one/stack/carousel/wall/scroll), `anim`, `badge` (stars/verified/heart/fire/count/glow/none), `bg` (dim/blur/color/none; blur is a shrink-and-stretch of the canvas, since Safari has no canvas `filter`), `per` (seconds per review), `t1` opening line (drawn with the `hook` graphic), `t2` ending line (the `linkbio` graphic, plus `confetti`) and `frame`. Its length follows the number of reviews (`lengthOf`). With no video on the timeline it starts with the colour background.
- **B-roll builder** (`video-broll.js`, **🎞️ B-roll** in the timeline bar and a banner on the start screen; `video-broll.js` keeps both quick-maker banners in `#vsQuick`, right under the start screen's intro and above Recent videos): the creator adds clips (device, Vault or the timeline's own clips), picks a story template (`TEMPLATES`: Hook → Problem → Solution → CTA, Before → After, 3 reasons, Unboxing, How to use it, Myth vs truth, Day in my life, This vs that, POV / storytime, Honest review; each part has on-screen text, a style, `look` weights over `LOOKS` and a `say` word regex), and a module worker (transformers.js from jsDelivr) looks at three frames per clip with CLIP zero-shot (`Xenova/clip-vit-base-patch32`) and listens to the first 28 s with Whisper tiny (same model id as caption Fast mode, so the cache is shared). `arrange()` gives every part its best clip first, then the rest to their best part, with a small pull towards the order they were added; if the AI can't load, the clips keep their order. The review step lets the creator move clips between parts and edit each part's words. Building replaces the current video (`veNewProject`, the old one stays in Recent videos): talking clips keep their whole speech, other clips are cut to whole beats, one text track per part, and a beat made in the browser (`makeBeat`, WebAudio in an `OfflineAudioContext`, moods in `MOODS`, saved as a WAV) goes on its own audio track, quieter when someone talks.
- **Timeline toolbar** (`video-toolbar.js`, loaded after every script that adds buttons): sorts the `.timebar` buttons into one scrollable row of labelled sections (Add, Create, Edit, View; unknown buttons go to Create, and a MutationObserver sorts buttons added later), and moves the "Timeline" title into the corner left of the ruler (`.tl-title`, placed from the ruler's offsets). Find toolbar buttons with `.timebar button` (they're nested now), not `.timebar>button`. Each button is restyled like phone quick settings (`.tb-btn`: a round `.tb-ic` icon taken from the label's leading emoji/symbol, the name in `.tb-tx` below; names wider than the button scroll back and forth via `.tb-tx.run`); the button's `aria-label`/`title` keep the name, and a button whose text another script replaces is rebuilt. `tapshop-theme.css` skips `.tb-btn` in its generic button rules. Track names left of the lanes sit in a narrow column (68 px + 8 px row padding; `LANE_START` in `timeline-strips.js` and the ruler's left margin must match it), and names too long for it scroll the same way (`.strip-name.run`, also in `video-toolbar.js`).

Row 1: ← Studio, ⌂ Start and the name field (`#projectName` in a pill with a pencil, dashed until focused, a pink "tap to name it" inside it while it's Untitled). ## Payments and files (be careful here)

- Paid orders are marked paid both on the thank-you page and in the Stripe webhook. That path must stay **idempotent**, and the delivery email goes out exactly once.
- **Discount codes** (`lib/discounts.ts`, `/dashboard/discounts`): a code takes a percent or a fixed amount off one product or the whole store, with an optional use limit and last day. The price is worked out only in `startCheckout`; `previewCode` just shows it to the buyer. Stripe gets the lower price as `unit_amount`, not a Stripe coupon, so `markPaid` needs no changes. Uses are counted from orders (`usedOrders`): paid and refunded ones, plus unpaid ones from the last 35 minutes, which is why checkouts with a code close after 31. `startCheckout` locks the code row while it checks the limit and creates the order. A 100% code skips Stripe like a free product; prices that land between 0 and `STRIPE_MIN_CENTS` are refused. The affiliate page `extras.code` is a different thing: text the creator shows visitors.
- **Creator affiliate programs** (`lib/affiliates.ts`, `/dashboard/affiliates` for the creator, `/dashboard/promote` for affiliates, public sign-up at `/<handle>/affiliates`; not the same thing as the AFFILIATE product type): any TapShopUGC user joins instantly (`Affiliate` row, `memberId` = their own Creator) and shares `/r/<code>` or `/r/<code>/<productId>` (`lib/refLink.ts`), which counts the click and sets the `ts_ref_<creatorId>` cookie for `affiliateDays`. `startCheckout` reads that cookie (never for the affiliate's own email), stores `affiliateId` and `commissionCents` (product `affiliatePercent` ?? creator's; 0 = left out) on the order, and passes the commission as the direct charge's `application_fee_amount`, so it lands in the platform balance. `markPaid` sets `commissionStatus` HELD and emails the affiliate. Vercel Cron (`vercel.json`, `CRON_SECRET`) calls `/api/cron/affiliate-payouts` daily: `payCommissions` transfers HELD commissions older than `HOLD_DAYS` to the affiliate's connected account (idempotency key per order; failures keep HELD with Stripe's reason in `commissionNote`, shown to both sides and in Admin). `charge.refunded` runs `cancelCommission`: refunds the application fee to the creator and reverses a transfer already sent. Connected accounts request the Accounts v2 `recipient` configuration (`stripe_balance.stripe_transfers`) so they can receive commissions; older accounts add it when they press Set up affiliate payouts (`connectStripe`).
- Paid files are private. They are only served through `/api/download/<token>` after the order is checked. Never give a paid file a public URL.
- Charges are direct charges on the creator's connected account. `ALLOW_PLATFORM_CHARGES` is for local testing only.

## Git and PRs

- Work on a branch and open a PR into `main`; don't push to `main` directly.
- Commit messages are short, plain English and describe what the user gets, e.g. "Let the portfolio video section hold several videos".
- Never commit `.env*` files (except `.env.example`), `/storage`, or secrets.
